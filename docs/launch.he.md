סדר מומלץ: 1 ← 2 ← 3 (מתחילים מוקדם, DNS לוקח עד יום) ← 4 ← 5 ← 6 ← 7.

## 3. Resend - שליחת קישורי הכניסה

השולח המובנה של Supabase מוגבל לכ-2 הודעות בשעה ושולח רק לחברי הצוות בארגון Supabase. בלי שולח חיצוני, שותפים חדשים לא יקבלו קישור. גם תבניות הדוא"ל בעברית (`supabase/templates/`) נכנסות לתוקף רק עם שולח חיצוני.

✋ אתם:
1. נרשמים ב-resend.com (התוכנית החינמית מספיקה).
2. **Domains ← Add Domain** ומוסיפים את הדומיין מסעיף 2.
3. מעתיקים את רשומות ה-DNS שמופיעות (SPF, DKIM, ומומלץ גם DMARC) לניהול ה-DNS אצל הרשם. ממתינים עד שב-Resend יופיע **Verified** (מדקות ועד יום).
4. **API Keys ← Create API Key** עם הרשאת Sending בלבד. שומרים את המפתח במנהל סיסמאות. **לא שולחים אותו בצ'אט.**
5. מודיעים ל-Claude שהדומיין מאומת.

🤖 Claude: מפעיל את קטע `[auth.email.smtp]` ב-`supabase/config.toml` עם כתובת השולח `no-reply@הדומיין`.

✋ ואז אתם, בטרמינל של הפרויקט (המפתח רק אצלכם):
```powershell
$env:SUPABASE_AUTH_SMTP_PASS = "re_המפתח_שלכם"
npx supabase config push --linked
```
כך שולח הדוא"ל ותבניות העברית עולים לפרויקט הפיתוח. אותו דבר יקרה בסעיף 4 לפרויקט הייצור.

## 4. פרויקט ייצור ב-Supabase (`ideas-prod`)

✋ אתם:
1. באותו ארגון Supabase ("trip ideas", שני בעלים): **New project**, שם `ideas-prod`, אזור **Frankfurt (eu-central-1)**. סיסמת מסד הנתונים - למנהל הסיסמאות.
2. החלטה על תוכנית: **Pro** כוללת גיבוי יומי אוטומטי. התוכנית החינמית בלי גיבוי, והמפרט (סעיף 10) קובע שהיא לא מתאימה להשקה. כדאי לבדוק את המחיר העדכני באתר.
3. שולחים ל-Claude את ה-Reference ID של הפרויקט (מופיע בכתובת הפרויקט ובהגדרות). זה לא סוד.

🤖 Claude:
1. מעלה את כל המיגרציות ואת ה-seed (שם המרחב, 7 הקטגוריות, כתובות השותפים) לפרויקט החדש, בלי לשנות את הקישור לפרויקט הפיתוח: `npx supabase db push --linked --project-ref <ref> --include-seed`.
2. מפעיל ב-`config.toml` את קטע `[remotes.production]` עם הכתובת מסעיף 2, ומעלה את הגדרות הכניסה: `config push --linked --project-ref <ref>` (אתם מגדירים לפני כן את `SUPABASE_AUTH_SMTP_PASS` כמו בסעיף 3).
3. מריץ את בדיקת המפתח הציבורי על הייצור (קריטריון 19).

## 5. אירוח ב-Vercel

✋ אתם:
1. נרשמים ב-vercel.com עם GitHub, יוצרים Team ומוסיפים את השותף השני.
2. **Add New ← Project** ובוחרים את המאגר `ideas-space`. ההגדרות כבר בקובץ `vercel.json` (Vite, תיקיית `dist`, ניתוב לכל המסכים).
3. **Environment Variables** - שני משתנים, לסביבת **Production**:
   - `VITE_SUPABASE_URL` = כתובת פרויקט הייצור (`https://<ref>.supabase.co`)
   - `VITE_SUPABASE_ANON_KEY` = המפתח הציבורי (anon) של פרויקט הייצור
   
   ולסביבת **Preview** - הערכים של פרויקט הפיתוח (כדי שגרסאות ניסיון לא יגעו בייצור).
4. **Deploy**.
5. **Settings ← Domains** - מוסיפים את הכתובת מסעיף 2 ומעדכנים את רשומת ה-DNS ש-Vercel מבקש.

מעכשיו כל דחיפה לענף `main` מעלה גרסה חדשה לאתר.

### בדיקת שחזור (קריטריון 15, ואחר כך פעם בחצי שנה)

1. ✋ יוצרים פרויקט Supabase זמני לבדיקה (למשל `ideas-restore-test`) ושולחים את ה-Reference ID.

4. 🤖 טוענים לפרויקט הבדיקה: `npm run import -- exports/<date>/ideas-space-<date>.json --project-ref=<test-ref>`. הסקריפט משווה את מספר השורות בכל טבלה.

בדיקה מהירה בלי פרויקט נוסף: `npm run import -- <file.json> --offline`.
